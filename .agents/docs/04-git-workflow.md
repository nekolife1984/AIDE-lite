# Gitでの変更・共有

課題ファイルが進捗の正本であり、Gitはその変更履歴と共有に使う。GitHub Issue／Projectは使わない。

## 作業前

- `git status`で既存変更を確認し、他の作業者の変更を混ぜない。
- 対象課題ファイル、完了条件、依存課題を確認する。
- 作業開始時に状態を`in_progress`へ更新する。

## 作業中

- 実装・文書・検証のまとまりごとに課題ファイルの進捗を更新する。
- コード変更と課題記録を同じ変更セットに含め、検証結果を実行後に記録する。
- 中断する場合は未解決点と具体的な次の作業を記録する。

## 共有

チームの通常のGit運用（ブランチ、レビュー、Pull Request）で変更を共有する。PR本文では課題IDを参照し、課題ファイルの完了条件と照合できるようにする。PRがマージされた後、完了条件を再確認して課題を`done`にする。

課題ファイルだけの変更でも、他の変更と同様に差分を確認する。不要なログ、秘密情報、一時ファイルをコミットしない。複数人で同じ課題ファイルを同時編集しない。
